## Naming rules

1. Governed Brainbox folders and documentation files end in `_BRAINBOX`, except genuine technical-convention names such as `.gitignore`, `.env.example`, and standard package/configuration files.
2. A parent path carries the full domain identity. A child record uses a stable concise infix where that convention is approved.
3. The V003 Governance parent is `GOVERNANCE_BRAINBOX/`; its children use `_GOV_BRAINBOX.md`. The parent name is not repeated in every child filename.
4. Use the exact names in the frozen V003 tree. A proposed or historical name is not approval to create or rename a path.
5. Inspect actual content and authority before assigning a destination. Filename similarity alone is not sufficient evidence.
6. Do not rename, move, or retire an existing source without an individually authorized ticket and verified destination.

## Provenance and examples

The concise `GOV` infix was normalized during V003 Phase 01. The final approved names are represented in the frozen Specification §8 and originated in the V003-P02 Governance Naming Normalization discussion. M03 implements those names; it does not migrate unapproved historical Governance proposals.
