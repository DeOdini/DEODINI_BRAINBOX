## 5. Retained Change Request Pattern (Reusable Template for Any AI Agent)

The following pattern is retained as a standing instruction for any AI agent that is instructed to create, modify, or execute a change request within the BRAINBOX environment. This pattern is derived from prior accepted requests and must be followed as the baseline for future change operations.

### 5.1 Constant Rule

The only constant across all change requests is this file:

**`BRAINBOX/FQ_MUST_README.md`**

This file may only be changed if an AI agent is specifically and explicitly instructed to change it. Absent such explicit instruction, `FQ_MUST_README.md` must remain intact and unmodified.

### 5.2 Variable Elements

The following elements may vary from one request to another and must be adapted per instruction:

- The number of requests (e.g., one request, two requests, three or more).
- The names of the target request file (e.g., `FUNC_REQ_BRAINBOX.md`, or another designated name).
- The folder path (e.g., `BRAINBOX/`, or another designated folder).
- The names of the agent-specific output files (e.g., `CHATGPT_BRAINBOX.md`, `CLAUDE_BRAINBOX.md`, etc.).
- The naming of each request’s header, which must reflect what the request is about.

### 5.3 Standing Instruction Pattern

When an AI agent is instructed to make any sort of change, the following pattern must be applied:

1. **Designate a request file.**  
   The agent must create a request file within the designated folder (e.g., `BRAINBOX/FUNC_REQ_BRAINBOX.md`). The entire content of each function request must be included in this file, with each request given a header that accurately reflects its subject.

2. **Compile all requests into the request file.**  
   If multiple requests are issued, all of them must be contained within the request file. Each request must be clearly separated and labeled under its own corresponding header.

3. **Create or update the compliance file.**  
   The agent must create or update `FQ_MUST_README.md`. Within this file, the agent must cite the request file (e.g., `FUNC_REQ_BRAINBOX.md`) as a **mandatory read** for all AI agents before carrying out, executing, or performing any tasks, commands, or operations given to them.

4. **Enforce the follow-up chain.**  
   After an AI agent has read the request file, it must follow up with the other folders, files, and documents listed within that request file, in the order and manner specified.

5. **Preserve the constant.**  
   `FQ_MUST_README.md` must remain the single constant file. It may only be modified when an AI agent is explicitly instructed to do so.

### 5.4 Canonical Example (Retained from Prior Accepted Request)

The following is the retained, canonical example of the pattern in practice:

> I want to create a `FUNC_REQ_BRAINBOX.md` file within the `BRAINBOX` folder.  
> An AI agent (e.g., ChatGPT) is to execute this and create the file.  
> Both entire function requests should be included within `FUNC_REQ_BRAINBOX.md`, naming each request’s header according to what the request was about.  
> The AI agent should also create a `FQ_MUST_README.md`. Within `FQ_MUST_README.md`, the agent should cite `FUNC_REQ_BRAINBOX.md` as a mandatory read for all AI agents before carrying out, executing, or performing any tasks, commands, or operations given to them. After which, once an AI agent has read `FUNC_REQ_BRAINBOX.md`, they should follow up with the other folders, files, and documents listed within.

### 5.5 Adaptation Rule

- The numbers, folder names, and file names in Section 5.4 are illustrative and may vary according to the request sent to an AI agent.
- The naming of each request header may vary according to the subject of the request.
- The only element that must remain constant is `FQ_MUST_README.md`.
- `FQ_MUST_README.md` may be changed **only** if an AI agent is specifically instructed to change it.
